# GitHub 浏览器操作已知坑点

这里记录实战中踩过的坑，新 agent 先读再动手。

## 1. fill 全文替换 README（2026-10-08）

用 fill 把整个 README 内容替换掉，容易报 verification mismatch，且编辑页可能失去响应。之后改单行一律用键盘定位插入。

## 2. 键盘输入错位（多次）

浏览器 type 输入工具有时会把文本插到文档顶部固定位置或过期光标处，而不是实时光标位置。症状：内容出现在文档中部/顶部。处理：立即 `Ctrl+Z` 撤销重来；如果反复错位，改用编辑器查找替换框（正则模式）做精确插入。

## 3. fill 换行翻倍（2026-10-09）

fill 写入时连续换行数会被按 k→2k-1 翻倍。如果必须整体写入（原文+新增），先拿小段对照测试确认规律，再按 `(k+1)/2` 补偿换行数写入，最后全文校验。

## 4. localhost 连不到（2026-10-09）

曾尝试在本机起 `python3 -m http.server` 让浏览器任务从 `http://127.0.0.1:8765/` 复制文件内容。失败：浏览器跑在云端租赁 VM 上，127.0.0.1 指向 VM 自身。结论：用 `browser.spawn_task` 的 `files` 参数传文件授权，字节直达。

## 5. GitHub App 无写权限（2026-10-08）

`meta-muse-ai` 这个 GitHub App 自身就没有申请写权限（Administration / Contents 都没有），API 建库、写文件一律 403 `Resource not accessible by integration`。重装 App 没用——用户开权限的前提是 App 先申请了。所有写操作走浏览器。

## 6. 浏览器 approval 弹窗（2026-10-08）

用户要求"GitHub 站点永久准许，不要总让我审核"。事实：开关只能在 Muse App 的 **Settings → Connectors → Browser**（或 Permissions 标签页）由用户自行把"访问网站""提交表单"设为 Allow，agent 无权更改。已提醒用户利弊。

## 7. 上传时重名文件（2026-10-09）

一次传 21 个文件时，根目录和 `assets/template/` 各有一个 `README.md`。靠内容特征区分（以 `# Feishu Bridge` 开头的是根目录版），曾误传一次，发现后用正确版本覆盖。教训：任务指令里写明判别方法。

## 8. 目录上传三步走（2026-10-09）

GitHub 网页上传不会自动建目录。可靠流程：`Create new file` 建 `<dir>/.gitkeep` 占位 → 进目录页 `Upload files` → 删 `.gitkeep`。21 个文件、7 个目录一次跑通。

## 9. 编辑器状态污染要换干净会话（2026-10-09）

一次 README 加行任务里，浏览器任务在同一个编辑器会话中尝试 120+ 次（type 错位、替换框状态卡住、长文本截断），CodeMirror 内部状态被污染后越试越糟。教训：连续失败 3 次就停，换一个全新的浏览器任务（干净会话）重做，一次就成功了。不要在被污染的会话里死磕。
